## 一、项目概述

- **主控**：华大 HC32F460PETB（Cortex-M4，LQFP100），使用官方 DDL 库 `HC32F460_DDL_Rev3.3.0`。
- **业务**：直流电机推窗（圆弧开窗/关窗）控制系统。
- **通信**：RS485 总线，Modbus RTU 从机协议（0x03 读保持寄存器 / 0x06 写单寄存器 / 0x10 写多寄存器）。
- **调试**：SEGGER RTT（`RTT/` 目录），日志开关集中在 `Utils/rtt_manager.h`。
- **IDE/构建**：Keil MDK，工程位于 `template/MDK/`，无 CI。

### 板卡版本

`template/source/main.h` 中通过宏控制两种硬件板（用户提到的宏实际名为 **`BOARD_VERSION`**，不是 BOARD_VISION）：

```c
#define BOARD_VERSION   0   // 0=原HB_chuchai板(当前) 1=整合板HandB
```

当前生效为 `BOARD_VERSION = 0`（原板）：
- 电机控制：GPIO 模式（PB8/PB9 直接高低电平，`MOTOR_CONTROL_MODE = 0`，无 PWM 缓启缓停）
- 电流传感器：霍尔型（零电流 1650mV，灵敏度 264mV/A）
- 母线电压 ADC：PA04 / CH4
- RS485 DIR：PB14
- 分压电阻：见文末差异说明（文档与代码不一致）

### 源码根目录

所有业务代码位于：

## 二、分层职责总览

| 层 | 目录 | 职责 | 与用户描述对应 |
|----|------|------|----------------|
| 入口 | `template/source/main.c` | 上电初始化顺序 + 主循环调度 | 从这里开始看 |
| App | `App/` | 系统初始化和主循环（App_Motor_Project）、Modbus 协议（App_Modbus）、故障聚合与清除（App_FaultHandler） | 功能控制、故障管理、通讯 |
| Dev | `Dev/` | 设备抽象（dev_xxx）、发布/订阅总线（EventBus）、设备注册/调度/互斥（device_manager） | 设备层 + 总线 + 设备管理 |
| Adp | `Adp/` | 直接操作外设寄存器/中断的驱动（PWM、ADC、GPIO、RS485、霍尔、时钟、DMA、Flash） | 功能封装（部分未全部使用） |
| Utils | `Utils/` | 参数管理层、扇区存储引擎、角度管理、TickTimer、消息队列、环形缓冲、锁、RTT 日志开关 | 功能补充 |

依赖方向（设计意图）：`main → App → Dev → Adp`，`Utils` 被各层共用；App 与 Dev 之间通过 **EventBus 事件 + DeviceManager 设备接口** 解耦。

## 三、入口与启动流程

### 3.1 main.c

```c
Hardware_Init();      // 时钟/GPIO/外设初始化
RS485_Init();         // USART + DIR 引脚 + 接收中断 + 帧队列
Modbus_Init();        // 参数 Flash 加载(Param_Init) + 实时数据初始化 + 清故障
ESystem_Init();       // EventBus + DeviceManager + 设备注册/初始化 + RunAngle
// Motor_Pwm_Init();  // 已注释（BOARD_VERSION=0 时不用 PWM）
FaultHandler_Init();  // 订阅电压/电流告警事件（勿在 Modbus_Init 里重复调用）
EventBus_Enable();    // 开门控：此后 Publish 才会真正执行回调

while (1) {
    ESystem_MainLoop();            // 1ms 节拍：过流事件 + 设备更新 + RunAngle
#if MOTOR_CONTROL_MODE == 1
    PWM_Update(...);               // 仅整合板
#endif
    RS485_Poll();                  // 帧解析 + 发送队列
    Modbus_Poll();                 // 实时数据刷新 + 收帧处理
}
```

### 3.2 ESystem_Init（App/App_Motor_Project.c）

1. `EventBus_Init()` 清零订阅表；
2. `DeviceManager_Init()`（超时 500ms、互斥开、不自动订阅）；
3. `RegisterAllDevices()` 注册设备；
4. `SetupEventBusSubscriptions()` 订阅事件；
5. **先初始化电机仲裁器** `Device_Init(ID_MOTOR)`，再初始化其余设备；
6. `SetDeviceUpdateIntervals()` 设置各设备更新时间片；
7. `DeviceManager_EnableAllUpdate()`；
8. `RunAngle_Init()`（绝对角度，Flash 扇区 55）。

### 3.3 主循环节拍

`ESystem_MainLoop()` 以 1ms 为门槛，顺序执行：
1. `Sensor_Device_ProcessPendingEvent()` —— ISR 里置的过流标志在主循环顶部立即发布（先于 RS485/Modbus）；
2. `Sim_ProcessInput()` / `Sim_PublishEvents()`（仿真模式，默认开）；
3. `ProcessDeviceUpdates()` → `DeviceManager_UpdateAll()`（按各自时间片调度）；
4. `RunAngle_Update()` —— 绝对角度增量跟踪；
5. `UpdateStatusIndicators()` —— 每 50ms 刷新 `g_status`（Keil Watch 用）。

> 注意：**电机仲裁每 50ms 执行一次**（`Motor_Update` 内部判断），事件回调本身是微秒级。

## 四、Dev 层：设备模型 + 事件总线 + 设备管理

### 4.1 DeviceManager（device_manager.c/h）

- 统一设备节点 `DeviceNode_t`：id、name、type、state、`private_data`、`DeviceOps_t`（init/deinit/read/write/control/update）、互斥锁、时间片（`update_interval`/`update_allow`）、订阅位图。
- 全局注册表 `s_device_registry[MAX_DEVICES=30]`。
- 时间片调度：`DeviceManager_UpdateAll()` 按 `update_interval` 轮询调用各设备 `update`。
- 提供 `Device_Init/Read/Write/Control`（带锁）与 `_NoLock` 版本。
- 命令码统一分配：`CMD_BASE_PWM=0x1000 … CMD_BASE_RTURN=0xA000`。

### 4.2 实际注册的设备（与设计文档的“完整注册”不同）

| ID | 名称 | 类型 | 时间片 | 说明 |
|----|------|------|--------|------|
| 0 | MotorArbitrator | MOTOR | 1ms | 电机仲裁器（核心） |
| 1 | PowerPositive | POWER | 1ms | 正电源（**模拟模式，未读真实 GPIO**） |
| 10 | MotorHall | HALL | 1ms | 霍尔转速/方向/脉冲 |
| 11 | ADC_Current | ADC | 1ms | 电流 ADC（PA5/CH5） |
| 12 | ADC_Voltage | ADC | 1ms | 电压 ADC（PA4/CH4，板0） |
| 13 | VoltageBus | SENSOR | 10ms | 母线电压计算 + 过/欠压 |
| 14 | SensorCurrent | SENSOR | 1ms | 电流计算 + 过流检测 |
| 15 | RTurn | SENSOR | 1ms | 旋转角度/限位/过流处理 |

**未注册/注释掉的设备**：PWM 电机设备（ID 9）、负电源（ID 2）、上下限位开关（5/6，已废弃，改用旋转限位）、正反转 IO 设备（7/8，IO 事件由总线直接进仲裁器）。

### 4.3 EventBus（EventBus.c/h）

- 每主题固定 **4 个订阅槽位**（二维数组），订阅按优先级插入（**值越小优先级越高**，0 最高）。
- 带“门控”：`EventBus_Enable()` 之前 Publish 只计数不回调（避免初始化阶段事件丢失/重入）。
- 当前 Topic 全集（与 EventBus事件拓扑说明.md 一致）：

| 3 | TOPIC_CAN_EVENT | 预留 | 未订阅 |

## 五、电机仲裁器（Dev/dev_motor.c）—— 系统核心

### 5.1 四队列模型

```
MotorDevice_t
 ├─ allow_fwd  按优先级升序（值小在前）
 ├─ allow_rev
 ├─ block_fwd  无序追加（去重）
 └─ block_rev
```

规则：**某方向能转 ⇔ 该方向 allow 非空 且 block 为空**（block 是安全锁，永远压过 allow）。
- `SetAllow`：若 block 非空则拒绝写入；移除同设备旧指令后按优先级插入。
- `SetBlock`：去重追加。
- 上电初始化：`block_fwd=[IO_FWD]`、`block_rev=[IO_REV]` → 默认双向锁死，必须收到 IO/RS485 运动指令才能解除。

### 5.2 仲裁决策（每 50ms）

```
1. fwd_cmd = (block_fwd 空 && allow_fwd 非空) ? allow_fwd[0] : NULL
   rev_cmd = (block_rev 空 && allow_rev 非空) ? allow_rev[0] : NULL
2. 双方都有：
   - 同一设备ID   → 冲突故障，不动
   - 优先级不同   → 选优先级高（值小）者
   - 优先级相同   → 死锁，不动
3. 有选中 → Motor_OnArbitrationFwd/Rev；无选中 → Motor_OnArbitrationStop
```

### 5.3 输出执行（BOARD_VERSION=0 → GPIO 模式）

- `Motor_OnArbitrationFwd/Rev/Stop` 直接操作 `PHU(PB8)/PHV(PB9)`，按 `g_AppParam.motor_dir` 决定映射；方向切换有消隐计时（FWD 50ms，`g_u8MotorForwardBlankActive` 供传感器跳过检测）。
- 仲裁决策里还会 `Device_Control(DEV_PWM_MOTOR_ID, ...)` 下发 PWM 指令——但**当前代码 DEV_PWM_MOTOR_ID 定义为 1**，与注册表里 ID1=PowerPositive 冲突（见文末差异 6）。GPIO 模式下该调用无实际效果。

### 5.4 事件回调 → 队列操作

| 回调 | 动作 |
|------|------|
| Motor_OnManualIO | RUN_FWD/REV → 移除本设备 block + 写 allow；STOP → 移除 allow + 写 block |
| Motor_OnRTurnLimit | 触发 → 写 block + 清 allow；释放 → 移除 block |
| Motor_OnVoltageAlarm | 触发 → 过压/欠压分别写 block_fwd+block_rev；释放 → 移除 |
| Motor_OnOvercurrentFwd/Rev | 触发 → 写 OVERCUR_FWD/REV 对应 block；释放 → 移除 |
| Motor_OnPowerEvent / OnHardLimit / OnSpeedFeedback | 电源/限位/转速反馈入口（当前实际业务主要走前几条） |

## 六、角度链路（霍尔 → 相对角度 → 绝对角度）

### 6.1 Adp/Motor_hall.c（硬件霍尔）

- PC13/PC14 边沿中断计数（EXTINT13/14），`motor_hall_update()` 每 1ms 计算 RPM、方向、堵转。
- **脉冲累加**：`g_s32HallPulseAccum`（全局，`App_Params.c` 定义）在 1ms update 中按方向累加（正转 +，反转 -），方向为 STOP/NONE 时回退最近有效方向；每次 1ms 都更新（不依赖 1s 定时器）。
- 每转脉冲数：`CALC_PULSES_PER_REV = 极对数 × 霍尔数(2) × 2`（默认 3×2×2=12）。

### 6.2 Dev/dev_rturn.c（旋转限位 + Pulse-Direct 角度）

- 每 1ms `RTurn_UpdateAngle`：
  - 角度 = `fMinAngle + g_s32HallPulseAccum × 360 / 12 / 减速比`（**Pulse-Direct 方案**，不再用 RPM 积分，消除加减速误差）；
  - `fCurrentAngle ≥ fMaxAngle` → 发 `TOPIC_RTURN_LIMIT(FWD)` 单方向锁正转（保留真实超调值，不钳位）；
  - `fCurrentAngle ≤ fMinAngle` → 钳位到 fMinAngle（关窗硬下限，不发限位事件）。
- 过流处理 `RTurn_HandleOvercurrent` / 主动检测（UpdateAngle 内查传感器告警）：
  - **关窗(REV)过流** → `RunAngle_TryCalibrate()` 成功则校准（角度归 fMinAngle、脉冲清零、`RunAngle_OnCalibration()`）；失败才报 `FAULT_BIT_OVERCURRENT_REV` + 双向锁。
  - **开窗(FWD)过流** → 直接报 `FAULT_BIT_OVERCURRENT_FWD` + `RTurn_PublishBidirectionalOvercurrent(1)` 双向锁。
  - 锁方向机制：`stcLockState` 记录锁死方向，锁定方向内忽略角度变化；`RTurn_Device_ClearLock` 解除。

### 6.3 Utils/App_RunAngle.c（绝对角度，独立于 dev_rturn）

- 维护 `s_abs_offset_x10`（0.1° 绝对偏移，RAM 上电从 Flash 载入），Flash 记录 `AbsAngleRecord_t` 存**扇区 55**（param_manager 多实例）。
- `RunAngle_Update()` 按霍尔脉冲增量积分（小数累加器防丢步）。
- 指令：设基准点/保存/回基准/回目标/点动（0x2725/0x2726/0x2727-0x2728/0x272B-0x272C），回目标通过发 `TOPIC_MANUAL_RS485` 运动指令实现。
- 校准钩子 `RunAngle_OnCalibration()`：把绝对偏移重置为 `close_limit_angle(0x271C)` 并立即存 Flash；`RunAngle_TryCalibrate()` 用 `calib_lower/upper_x10`（0x272A/0x2729）判断是否允许校准。
- 欠压自动保存：`RunAngle_Update()` 内检测欠压时把当前偏移写 Flash（掉电保护）。

> 用户提示成立：**角度管理放在 Utils 层**（App_RunAngle）与 Dev 层（dev_rturn）并存两套角度体系，职责上更接近业务/设备逻辑，后续可考虑上移。

## 七、传感与告警链（电流 / 电压 / 故障）

### 7.1 电流（Dev/dev_sensor.c）

- 电流公式：`I(mA) = (Vadc - 零点 - ZeroOffset) × 1000 / 灵敏度`；板0：零点 1650mV、灵敏度 264mV/A。
- 上电自动零点校准：120ms 等待 + 50ms 稳定，测得的零点偏移存 `stcCalibration.s32ZeroOffsetMv`（5s 超时置 0）。
- 过流检测：**时间窗口模式**（固定 `OVERCURRENT_MODE_TIME_WINDOW`），`u32TriggerWindowMs` 内持续超阈值才触发，`u32ReleaseWindowMs` 释放；也保留计数模式。
- 快速路径：ADC/定时器 ISR 里 `Sensor_OcIsrCallback` 置 pending 标志 → 主循环顶部 `Sensor_Device_ProcessPendingEvent()` 立即发布 `TOPIC_CURRENT_ALARM`（不等 1ms 轮询）。
- 清除：手动模式 `OVERCURRENT_CLEAR_MANUAL`，`Sensor_Device_ClearAlarm()` 发布解除事件。

### 7.2 电压（Dev/dev_voltage.c）

- `母线电压 = ADC电压 × 分压比 + 400mV 补偿`；过压/欠压带迟滞 + 连续触发计数，发布 `TOPIC_VOLTAGE_ALARM`。
- 清除：`VOLTAGE_CLEAR_MANUAL`，`Voltage_Device_ClearAlarm()`。

### 7.3 故障聚合（App/App_FaultHandler.c）

- `FaultHandler_Init()` 订阅 `TOPIC_VOLTAGE_ALARM(1)` 与 `TOPIC_CURRENT_ALARM(0)`，把告警映射到 `g_RealTimeData.fault_status`（0x2740 的 FAULT_BIT_xxx）。
- 清除：Modbus 写 `REG_FAULT_STATUS` → `App_Params.Param_WriteByReg` → `FaultHandler_ClearFault()` → 清设备告警 + `Motor_ClearVoltageBlock/Motor_ClearOvercurrentBlock` + 清故障位 + 发过流释放事件。

故障位定义（当前代码）：bit0 过压、bit1 正转过流、bit2 反转关流、bit3 复位、bit4 过载、bit5 堵转、bit6 欠压。

## 八、通讯链（RS485 + Modbus）

### 8.1 Adp/rs485.c

- USART 中断收字节 → 环形缓冲 → 帧解析器（空闲/超时判帧）→ `msg_queue`（RX_FRAME_QUEUE_SIZE=10）。
- 发送：`RS485_Send()` 入 TX 队列，DIR 引脚控制收发方向（板0 PB14）。
- 波特率 9600（`RS485_BAUDRATE`）。

### 8.2 App/App_Modbus.c

- `Modbus_Poll()`：先刷新实时数据（`Modbus_UpdateRealtime` → `RealTime_UpdateFromDevice`，宏 `APP_PARAMS_USE_DEV_RTURN` 已开，从 dev_rturn/dev_voltage/dev_sensor 读），再收帧处理。
- 帧处理：CRC16 校验 → 地址匹配（含**广播心跳**：addr=0 + 0x03 + 0x271F + 数量1）→ 功能码分发：
  - 0x03 读：`Param_ReadByReg`（配置、实时、故障、心跳等）；
  - 0x06/0x10 写：`Param_Validate`（限幅+取整）→ `Param_WriteByReg` → 配置类寄存器写 Flash + `App_ReloadConfig()` 热重载（不复位）；
  - 特殊寄存器：0x2725/0x2726/0x272B/0x272C → RunAngle 指令；0x2720 → App_Params 内部处理（解锁/停止/急停/正反，发 `TOPIC_MANUAL_RS485`）；0x2740 → 故障清除。
- `REG_CTRL_CMD(0x2720)`：bit0 解锁、bit1 上锁、bit2 急停、bit3 延时复位（1s）、bit4/bit5 正/反转（需先解锁且互斥）；读回 bit4/bit5 表示当前方向。

### 8.3 寄存器地图（简化）

- 0x2710 设备地址、0x2711 目标转速、0x2712 目标角度、0x2714/0x2715 过/欠压阈值(0.1V)、0x2716 过流阈值(mA)、0x271C/0x271D 关/开窗极限(0.1°)、0x271E 过流判定时间、0x271F 心跳(只读=node_id)
- 0x2720 控制命令、0x2721-0x2722 绝对角度RAM、0x2723-0x2724 Flash偏移、0x2725 绝对角度命令、0x2726 回基准阈值、0x2727-0x2728 目标角度、0x2729-0x272A 校准范围、0x272B-0x272C 点动
- 0x2730-0x2733/0x2737 实时转速/角度/电压/电流/方向，0x2740 故障状态
- 0x3710-0x3713 霍尔方向/电机方向/减速比/极对数（存 Flash，RAM 生效）

## 九、参数与 Flash 存储（Utils）

### 9.1 param_manager.c（磨损均衡引擎）

- 通用多实例：`Param_Init/Save`，魔数头尾 + CRC32 + 序列号 + 擦写计数。
- 主参数实例（App_Modbus.c）：`secStart=62, secEnd=56`（**扇区 56~62** 共 7 个扇区轮转，磨损均衡）。
- 绝对角度实例（App_RunAngle.c）：`secStart=55, secEnd=55`（单扇区）。

### 9.2 App_Params.c/h（寄存器读写分发）

- `g_AppParam`（AppParamRecord_t，packed 布局即 Flash 布局）、`g_RealTimeData`、`g_SimRealtimeData`、`g_s32HallPulseAccum`。
- `Param_ReadByReg` / `Param_WriteByReg` 是 Modbus 与参数/实时数据的唯一入口。
- 默认值集中在 App_Params.h（如过压 27.0V、欠压 21.0V、过流 1100mA、减速比 1183.0、开窗 88.0°、关窗 -2.0°）。

### 9.3 param_validator.c

- 每个寄存器一条规则（min/max/step），写入先限幅后取整（如角度 0.1° 精度）。

### 9.4 其它 Utils

- TickTimer：1ms SysTick 滴答 + 非阻塞延时。
- msg_queue：带优先级/覆盖策略/统计的消息队列（RS485 帧队列、日志用）。
- lock：互斥/自旋/递归锁（DeviceManager 互斥）。
- ring_buf：字节环形缓冲（RS485、ADC 原始数据）。
- rtt_manager：模块调试宏总开关 + `INTERVAL_DECLARE` 间隔打印器。

## 十一、仿真模式说明

- `App_Motor_Project.h`：`ENABLE_SIMULATION_MODE` 默认 1。
- `Sim_ProcessInput()` 基本为空壳；`Sim_PublishEvents()` 根据 `g_sim` 边沿发布 POWER / LIMIT_HARD / MANUAL_IO 事件（Keil Watch 改 `g_sim` 即可模拟）。
- 注意：`dev_power.h` 中 `POWER_SIMULATION_MODE` 是**无条件定义**的——即使关闭总仿真开关，电源设备也始终走模拟值（默认有电）。ADC/电流/电压走真实硬件路径。

## 十二、文档与代码的差异（辩证核对结果）

> 以下均为读代码后确认的差异，`.md` 文档仅供参考。

1. **宏名**：用户提到的 `BOARD_VISION` 实际为 `BOARD_VERSION`（main.h）。

2. **电压分压电阻**：`chuchai vs HandB.md` 与 CLAUDE.md 写“板0 = 110k/10k，分压比 12”；但 `Dev/dev_voltage.h` 代码为 `TOP=100000Ω(100k)`、`BOTTOM=3300Ω(3.3k)`（`VOLTAGE_DIVIDER_RATIO≈31.3`），且该文件注释仍写“110k+10k”。**以代码为准：100k/3.3k + 400mV 补偿**。（`dev_sensor.h` 中 1650mV/264mV/A 与文档一致。）

3. **心跳包**：CLAUDE.md 写“心跳包功能尚未实现”；实际 `REG_HEARTBEAT(0x271F)` 读=node_id、广播心跳（addr=0）均已实现（App_Params.c / App_Modbus.c），与 心跳包.md 一致。

4. **EventBus 事件拓扑顺序**：EventBus事件拓扑说明.md 称“RTurn 先于 FaultHandler（RTurn priority 1 先执行）”。实际优先级约定是**数值越小越高**：`FaultHandler_OnCurrentAlarm` 订阅 priority=0，`RTurn_OnCurrentAlarm` 订阅 priority=1，因此 **FaultHandler 先执行**。文档的时序描述与代码优先级相反。

5. **实时数据文档过旧**：`实时数据使用说明.md` 的故障位（FAULT_BIT_OVERCURRENT / OVERTEMP）与当前 App_Params.h（FWD/REV 双向 + 欠压 bit6，无 OVERTEMP）不一致。

6. **PWM 设备 ID 冲突（潜在缺陷）**：`dev_motor.c` 中 `DEV_PWM_MOTOR_ID=1` 且仲裁决策调用 `Device_Control(1, PWM指令)`，但注册表中 ID1 是 PowerPositive，ID9（ID_PWM_MOTOR）才是设计上的 PWM 设备且未注册。BOARD_VERSION=0（GPIO 模式）下无实际影响；切到整合板 PWM 模式前必须修正（把 PWM 设备注册到 ID1 或把宏改成 9）。

7. **文件编码**：CLAUDE.md 说 `dev_motor.c/h、dev_rturn.c/h、dev_voltage.c/h、App_Modbus.c` 均为 UTF-16LE。实测：`dev_motor.c`/`dev_rturn.c`/`dev_voltage.c` 是 UTF-8（无 BOM）；`dev_rturn.h`/`dev_voltage.h`/`App_Modbus.c`/`Adapter.c`/`main.h` 等为 UTF-16LE；`dev_motor.h` 等中文注释存在 GBK/UTF-8 混合（部分乱码）。**编辑前务必按文件实际编码处理**，文档清单已过时。

8. **CLAUDE.md 引用的“绝对角度.md”** 在项目根目录不存在（对应内容实际散落在 关窗基准点.md / App_RunAngle 等）。

9. **设备注册范围**：CLAUDE.md 架构描述列出了完整 Dev 设备族（dev_io/dev_hall/dev_pwm/dev_power 等），但**当前运行态只注册 8 个设备**（见第四节表），负电源、IO、限位开关、PWM 设备均被注释。

10. **电源仿真**：`POWER_SIMULATION_MODE` 无条件开启（见第十一节），与“关掉仿真即用真实硬件”的文档描述不完全一致。

11. **故障清除链路**：EventBus 定义了 `TOPIC_FAULT_CLEAR` 但代码未发布/订阅它，清除走 `FaultHandler_ClearFault()` 直调（App_Params → FaultHandler）。

## 十三、已知问题 / 改进建议

1. 修正 `DEV_PWM_MOTOR_ID`（差异 6），否则整合板 PWM 模式不可用。
2. `dev_motor.h` 等文件中文注释乱码/编码混杂，建议统一为 UTF-8 并整理。
3. 角度管理双轨（dev_rturn 相对角度 + App_RunAngle 绝对角度）职责边界不清，建议按用户意见把角度管理从 Utils 移到更合适层。
4. 心跳广播多从机同发会碰撞（心跳包.md 已提醒），实际部署建议只用定向心跳。
5. 大量预留 Topic/CMD/设备未使用，代码里存在较多注释掉的“设计意图”，维护时注意区分“设计”与“现状”。
6. `App_Modbus.c` 中 `FaultHandler_Init()` 调用被注释（避免重复订阅），而 `main.c` 调用它——改动初始化顺序时需留意。
7. 电压分压参数（100k/3.3k）与多处注释/文档不一致，改硬件或文档时需同步，避免误调。
