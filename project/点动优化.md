# 点动优化

> 目标:让点动模式(0x272B/0x272C)不再遵循回目标(0x2727/0x2728)的同一个停止阈值,或改用该阈值的三分之一(默认 0.6° → 0.2°)。

## 背景:阈值在代码中的使用位置

阈值 `g_AbsAngle.goto_zero_thresh_x10`(寄存器 0x2726)在**两个地方**被使用,两处都要改:

| 位置 | 函数 | 行号 | 作用 |
|------|------|------|------|
| 启动判据 | `RunAngle_GotoTarget()` | ~272 / ~280 | `dist > +thresh` → REV;`dist < -thresh` → FWD;否则"已在目标"不动 |
| 停止判据 | `RunAngle_Update()` | ~157 | `abs(dist) <= thresh` 或符号翻转 → 自动 ESTOP |

> ⚠ 只改停止判据不行:点动量小于完整阈值(如 0.5° < 0.6°)时,启动阶段会被"已在目标位置"分支吞掉,根本不会转。

---

## 方案A(推荐):给 GotoTarget 加"本次动作使用的阈值"参数

**改动文件**:仅 `App_RunAngle.c`(新函数如公开才动 `.h`)

### 1. 新增静态变量 + 带阈值参数的核心函数(拆分现有 `RunAngle_GotoTarget`)

```c
static int32_t s_move_thresh_x10;   /* 本次转动实际使用的阈值(启动时快照) */

/* 核心函数:门禁 + 方向判定,阈值由参数传入 */
void RunAngle_GotoTargetEx(int32_t thresh_x10)
{
    /* Gate 1 / Gate 2 不变... */

    s_move_thresh_x10 = thresh_x10;          /* ★ 记住本次阈值 */

    int32_t dist = s_abs_offset_x10 - s_target_x10;
    if (dist > thresh_x10) {                 /* 原来用 g_AbsAngle.goto_zero_thresh_x10 */
        ... REV ...
    } else if (dist < -thresh_x10) {         /* 同上 */
        ... FWD ...
    } else {
        ... already at target ...
    }
}

/* 原入口保留,供 0x10 回目标调用,用完整阈值 */
void RunAngle_GotoTarget(void)
{
    RunAngle_GotoTargetEx(g_AbsAngle.goto_zero_thresh_x10);
}
```

### 2. 点动函数改为传 1/3 阈值

```c
void RunAngle_JogFwd(uint16_t offset_x10)
{
    s_target_x10 = s_abs_offset_x10 + (int32_t)offset_x10;
    RunAngle_GotoTargetEx(g_AbsAngle.goto_zero_thresh_x10 / 3);   /* ★ 1/3 */
}

void RunAngle_JogRev(uint16_t offset_x10)
{
    s_target_x10 = s_abs_offset_x10 - (int32_t)offset_x10;
    RunAngle_GotoTargetEx(g_AbsAngle.goto_zero_thresh_x10 / 3);   /* ★ 1/3 */
}
```

### 3. 停止判据改用快照值

```c
if (s_goto_target_active) {
    int32_t dist = s_abs_offset_x10 - s_target_x10;
    if (abs(dist) <= s_move_thresh_x10          /* 原来是 g_AbsAngle.goto_zero_thresh_x10 */
        || (dist > 0) != (s_goto_zero_initial_sign)) {
        ... STOP ...
        s_goto_target_active = false;
    }
}
```

**优点**:启动和停止用同一阈值快照,中途 0x2726 热重载不影响正在进行的点动;回目标路径完全不受影响。

## 方案B(最小改动):加 `s_jog_active` 标志,两处做除法

```c
static bool s_jog_active = false;   /* 新加 */
```

- `RunAngle_JogFwd/JogRev` 里调 `RunAngle_GotoTarget()` 之前置 `s_jog_active = true`
- `RunAngle_GotoTarget` 内计算局部变量:`int32_t thresh = s_jog_active ? g_AbsAngle.goto_zero_thresh_x10 / 3 : g_AbsAngle.goto_zero_thresh_x10;`,方向判断用它
- `RunAngle_Update` 停止判据里同样计算这个 `thresh` 再用
- **⚠ 必须注意清除时机**:门禁拒绝、已到目标、停止这三个出口都要把 `s_jog_active` 清回 false,否则会污染下一次正常的回目标

**缺点**:容易漏清标志,不如方案A干净。

## 方案C:新增寄存器独立管理点动阈值(仅提及)

新增一个寄存器(如 0x272D/0x272E 区域,现为保留地址)专门存放点动模式的目标角度阈值,点动启动/停止判据改用该寄存器值,与回目标阈值(0x2726)完全解耦。需要扩展 `App_Params.h/c` 的寄存器定义与读写路径,以及 Flash 存储结构。

---

## 注意事项

1. **整数除法截断**:默认阈值 6(0.6°)÷3 = 2(0.2°),正好是三分之一;但若 0x2726 设为 1,`1/3 = 0`,点动退化为"零阈值";想要四舍五入可写 `(x + 1) / 3`。
2. **副作用**:点动量 < 有效阈值(如 0.1° < 0.2°)时,会被"已在目标位置"分支吞掉不动,这是阈值机制本身的语义,不是 bug。
3. **"完全不想要阈值"**:点动传 `0`,启动时只要 dist ≠ 0 就转;停止靠符号翻转(`(dist > 0) != s_goto_zero_initial_sign`)——越过目标点即停,误差为 1ms 采样粒度内的过冲。
4. 不需要动 `App_Modbus.c`、`App_Params.c`(方案C除外)、`.h`(除非公开 `RunAngle_GotoTargetEx`)。
