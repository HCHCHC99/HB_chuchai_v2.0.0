> 状态：**已实施并编译通过；2026-08-06 增量：采样 200µs、回落容忍(当前 0=严格连续)、反转屏蔽 50ms、窗口默认 10ms，待复测**

## 1. 背景与问题

- 当前配置：过流阈值 1.1A（寄存器 0x2716，`g_AppParam.current_upper_limit`），过流判定窗口 40ms（寄存器 0x271E，`g_AppParam.current_detect_ms`）。
- 期望行为：电流连续大于 1.1A 持续 40ms 即触发过流，电机停车。
- 实测现象：示波器测量触发时间在 **30ms ~ 100ms 之间波动**，不是稳定的 40ms。
- 结论：波动根源不在"40ms 计时"本身，而在**判定时机依赖主循环轮询**、**毫秒级时间量化**、**滤波滞后**与**噪声提前启动计时**。

## 2. 现状代码分析

### 2.1 三层采样传输链（现状）

```
ADC 硬件 (TMR0_1 CH_B → AOS → ADC1, 200µs/次, 5kHz)
  → Adc.c 适配层 (EOCA 中断 ADC1_SeqA_IrqCallback)
      ├─ 更新 pstcInst->u16LatestValue
      └─ 调用已注册回调 pfnCallback(value, channel)   [Adc.c:198-218]
  → dev_adc.c 设备层 (ADC_Device_OnDataReady, 中断上下文)
      └─ 原始值写入环形缓冲区 stcRawRing             [dev_adc.c:35-58]
  → dev_adc.c Update (主循环, DeviceManager interval=1ms)
      └─ 批量取出 → EMA(α=0.4) 滤波 → u16VoltageMv   [dev_adc.c:124-197]
  → dev_sensor.c Update (主循环, interval=1ms)
      ├─ Device_Read(ID_ADC_CURRENT) 读滤波值        [dev_sensor.c:153-180]
      ├─ Sensor_CalcCurrentInternal: (mV-零点-偏移)×1000/灵敏度 [dev_sensor.c:116-150]
      └─ Sensor_CheckOvercurrent: 时间窗口模式(nbDelay+tickTimer 毫秒) [dev_sensor.c:247-333]
          └─ 触发 → EventBus_Publish(TOPIC_CURRENT_ALARM)  [dev_sensor.c:285]
  → RTurn_OnCurrentAlarm → RTurn_HandleOvercurrent (锁方向/报故障)
      └─ RTurn_PublishBidirectionalOvercurrent → TOPIC_OVERCURRENT_FWD/REV
  → Motor_OnOvercurrentFwd/Rev → Motor_CmdList_SetBlock → Motor_ArbitrationDecision()
      └─ Motor_OnArbitrationStop(): GPIO_SET(PB8)+GPIO_SET(PB9)  [GPIO 模式, dev_motor.c:348-354]
```

### 2.2 时间误差拆解

从"真实电流越过阈值"到"GPIO 拉停"：

```
T_total = T_起点滞后 + T_滤波滞后 + 40ms(毫秒量化) + T_终点滞后 + T_执行
```

| 误差项 | 说明 | 量级 |
|---|---|---|
| 起点滞后 | 窗口起点=传感器 Update 第一次看到超限；真实越限后最多等一个主循环周期 | 0 ~ T_loop |
| 滤波滞后 | 使用 EMA(0.4) 滤波值，越限晚于真实值 | 数 ms |
| 毫秒量化 | tickTimer 1ms；nbDelay 判定 elapsed>=40 | ±1ms |
| 终点滞后 | 40ms 到点后需下一次 Update 才 `nbDelay_IsComplete` | 0 ~ T_loop |
| 执行 | 事件发布→RTurn→仲裁→GPIO 拉停（同步调用） | 微秒级 |

- **提前触发（30ms）**：计时起点比示波器参考更早——噪声/毛刺让滤波值提前越限启动计时（当前无毛刺剔除），或零点偏置导致计算电流偏大。
- **延迟触发（100ms）**：主循环被 RS485/Modbus/打印/其他设备 Update 拖慢时，起点+终点滞后同时放大（40ms + 2×T_loop）；若电流在阈值附近抖动，任一非超限采样点都会 `nbDelay_Stop` 清零窗口，进一步拉长。

### 2.3 已排除因素

- 启动消隐（FWD 50ms）：用户实测场景不在堵转位置启动，与波动无关（实现时仍需处理，见 5.7）。

## 3. 优化目标

1. 过流窗口判定精度：**40ms ± 1 个采样周期（±200µs）**，与主循环调度完全解耦。
2. 不破坏现有下游链路：RTurn 锁方向/报故障、Motor 仲裁、EventBus、GPIO 停车逻辑全部保持不变。
3. 窗口/阈值运行时可配（485 → 0x271E / 0x2716），**不写死 40ms / 1.1A**。
4. 改动最小、风险可控。

---

## 4. 方案选择：方案二（ISR 判定 + 置标志，主循环走现有链路）

### 4.1 候选方案对比

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| 一：ISR 直接发布事件 | ADC 中断里判定后直接 EventBus_Publish | 延迟最小 | EventBus 非中断安全；RTurn/Motor 处理重（故障位、锁状态、嵌套发布、队列、GPIO）都在 ISR 执行，有并发风险 |
| **二：ISR 置标志，主循环处理（选定）** | ISR 只做判定+置标志+缓存事件；主循环顶部检查后走现有链路 | 检测精度根治；下游零改动；无 ISR 并发风险 | 执行延迟增加 0~1 个主循环周期（固定、毫秒级） |
| 三：ISR 直接 GPIO 拉停 | 中断里直接拉 PHU/PHV | 最快最可靠 | 绕开 RTurn/Motor 业务逻辑（故障位、锁方向、角度校准联动缺失），需额外锁存防仲裁器再启动 |

### 4.2 方案二总体结构

```
ADC EOCA 中断（200µs）
  └─ dev_sensor 注册的回调（ISR 内）
       ├─ Timer6_Timebase_UpdateTimestamp() → 取 µs 时间戳
       ├─ 原始值 → 电流换算（编译期灵敏度 + 零点偏移，未校准用理论零点）
       ├─ 消隐检查：消隐中 → 清状态 return
       ├─ 阈值比较 + 过流状态机（时间戳窗口，µs 精度，回落容忍宏可配）
       └─ 窗口满足 → 写事件缓存 → 置 pending 标志（不发布）

主循环 ESystem_MainLoop 最顶部（RS485/Modbus 之前）
  └─ 检查 pending 标志
       ├─ 有 → 拷贝事件 → 清标志 → EventBus_Publish(TOPIC_CURRENT_ALARM)
       │      → 现有链路 RTurn → Motor → 仲裁 → GPIO 拉停（零改动）
       └─ 无 → 继续正常流程
```

## 5. 详细设计

### 5.1 时间戳：Timer6

**硬件参数（已核实）**

- Timer6_2，时钟 = PCLK0 / 64；PCLK0 = 200MHz（`Sysclk.h:63` SYSTICK_PCLK0_DIV = DIV1）
- 计数频率 = 200MHz / 64 = **3.125MHz → 每计数 0.32µs**
- 16 位自由运行计数器，**每 ~20.97ms 回绕一次**（`timer6_timebase.c:5-6, 38-44`）

**关键前提（现有代码的坑）**

- `Timer6_Timebase_GetTimestamp()` 返回的 µs 累加器 `s_total_elapsed_us` **只有调用 `UpdateTimestamp()` 时才推进**。
- 当前 `UpdateTimestamp()` 仅在 `motor_hall_update()`（主循环设备 Update，1ms 级）调用（`Motor_hall.c:570`）→ **现有时间戳量化精度约 1ms，不是 µs**。

**本方案用法**

- 在 **ADC EOCA 中断入口**调用一次 `Timer6_Timebase_UpdateTimestamp()`，再 `Timer6_Timebase_GetTimestamp()` 取当前时刻。
- 效果：累加器以采样周期推进 → 时间戳量化 ≤ 一个采样周期；uint64 无溢出；16 位回绕自动处理；**任意窗口长度（最大 65535ms）均兼容**。
> 注：2026-08-06 发现原 `Adc.h` 的 `ADC_SAMPLE_INTERVAL_US` 为 1000U（1ms 采样），已改回 200U（200µs/5kHz）；本方案精度前提以 200µs 为准。
- 若后续要求更高精度（如 2s 窗口误差 <1ms），可给 timer6_timebase 增加"原始计数累加、一次性换算 µs"的接口（避免逐次整数截断），本设计暂不强制。

**注意事项**

1. `UpdateTimestamp()` 调用点统一到 ADC ISR；**移除 `motor_hall_update()` 中的调用**（`Motor_hall.c:570`），避免主循环与 ISR 竞争 `s_last_timer6_counter` / `s_total_elapsed_us`（uint64 非原子）。移除对霍尔无影响：计数/脉冲间隔走 `GetDelta()`（裸计数器，独立状态），`GetTimestamp()` 仍由 ADC ISR 以 200µs 更新（比原来 1ms 更准）。
2. `GetTimestamp()` 返回 uint64，32 位 MCU 读取非原子；ISR 内（只有 ISR 写、ISR 读）使用无问题；主循环侧若读取（调试用）容忍偶发撕裂值。

### 5.2 回调注册

- 现有 Adp 层（Adc.c）的通道回调 `pfnCallback(value, channel)` 已被 dev_adc 的 `ADC_Device_OnDataReady`（写环形缓冲）占用。
- 在 **dev_adc 层新增一套"按通道注册回调"接口**（如 `ADC_Device_RegisterCallback(channel, cb, ctx)`），与现有环形缓冲链路并存：
  - 环形缓冲 + EMA 滤波：保留，供遥测/调试使用；
  - 新回调：供 dev_sensor 注册过流判定回调（中断上下文）。
- dev_sensor 在 `Sensor_Device_Init` 时注册；回调签名建议 `void (*)(uint16_t raw, uint8_t ch, void* ctx)`（时间戳在回调内自行获取，避免传递 64 位参数）。

### 5.3 ISR 过流状态机（伪代码，当前实现）

```
// 状态
enum { OC_NORMAL=0, OC_TIMING=1, OC_TRIGGERED=2 }  oc_state;
uint64_t oc_start_us;          // 当前窗口起始 µs（每次 0→1 更新）
uint32_t latched_window_us;    // 进入 OC_TIMING 时锁存：stcConfig.u32TriggerWindowMs × 1000
int32_t  latched_threshold_ma; // 进入 OC_TIMING 时锁存：stcConfig.s32OvercurrentThresholdMa
uint16_t below_count;          // 连续低于阈值采样计数（回落容忍）
uint8_t  attempt_done;         // 1=本轮过流尝试已结束（触发/清除）
// 调试变量（volatile，Keil Watch）
g_dbg_isr_oc_state, g_dbg_isr_oc_start_us, g_dbg_isr_oc_elapsed_us,
g_dbg_isr_oc_window_us, g_dbg_isr_oc_cur_ma, g_dbg_isr_oc_reset_cnt

void Sensor_OcIsrCallback(uint16_t raw_adc, uint8_t ch)
{
    // 0) 时间戳（先更新再取，量化 ≤ 采样周期）
    Timer6_Timebase_UpdateTimestamp();
    uint64_t now_us = Timer6_Timebase_GetTimestamp();

    // 1) 消隐：完全不判定，清状态 + 清回落计数
    if (g_u8MotorForwardBlankActive || g_u8MotorReverseBlankActive) {
        oc_state = OC_NORMAL; below_count = 0;
        return;
    }

    // 2) 电流换算（与 Sensor_CalcCurrentInternal 一致，纯整数）
    //    mV = raw * 3300 / 4095；mA = (mV - zero - offset) * 1000 / 灵敏度
    //    未校准用理论零点；灵敏度为编译期常量

    // 3) 阈值比较 + 状态机（严格连续 + 回落容忍，free-run）
    if (abs_ma >= 比较阈值) {
        below_count = 0;
        if (oc_state == OC_NORMAL) {
            oc_state = OC_TIMING; oc_start_us = now_us;
            锁存 window/threshold；
            if (attempt_done) { attempt_done = 0; reset_cnt = 0; }  // 新一轮过流尝试
        } else if (oc_state == OC_TIMING) {
            if ((now_us - oc_start_us) >= latched_window_us) {
                oc_state = OC_TRIGGERED; attempt_done = 1;
                if (pending == 0) { 写缓存; 记录 T0(trigger_us/stop_measure=1); pending=1; }
            }
        }
        // 状态2：保持，不重复发布
    } else {
        below_count++;
        if (below_count >= SENSOR_OC_DROP_TOLERANCE_SAMPLES) {
            // 回落超容忍：窗口作废（原状态为计时中则 reset_cnt++ 诊断）
            oc_state = OC_NORMAL; below_count = 0;
            if (原状态 == OC_TIMING) reset_cnt++;
        }
        // 未超容忍：窗口继续走（free-run，墙钟不暂停）
    }
}
```

**关键语义**

- **严格连续 + 回落容忍**：`SENSOR_OC_DROP_TOLERANCE_US` 宏可配（当前 0 = 严格连续，任一低于阈值采样点立即清零；>0 时允许回落 <N ms 不清零，窗口墙钟继续走）。
- **每个过流点独立判定**：触发 ⇔ 存在一段"无 >容忍 中断"的窗口（当前默认 10ms）墙钟段；与"每个点各自开窗口"结果等价。
- **防重复**：`OC_TRIGGERED` 后不再置 pending（同一持续过流过程只触发一次）。
- **自动重新武装**：状态2 回落超容忍后回到 `OC_NORMAL`；手动/485 清除作为强制复位兜底。
- **参数锁存**：进入 `OC_TIMING` 时锁存窗口/阈值，本次过程不受运行中 485 改参影响。
- **reset_cnt**：仅状态1 计时中被回落清零才 +1；新一轮过流尝试（触发/清除后再次 0→1）时清零；急停打印在清零前输出该值。

### 5.4 ISR → 主循环交接协议

- 数据：`volatile uint8_t g_u8SensorOcPending;` + `volatile Current_AlarmEvent_t g_sensor_oc_cache;`
- 写入方（ISR）：
  1. 仅当 `g_u8SensorOcPending == 0` 时写缓存（防止覆盖未处理事件）；
  2. **先写数据，再置标志**。
- 读取方（主循环，ESystem_MainLoop 顶部）：
  1. 检测 `g_u8SensorOcPending == 1`；
  2. **先拷贝数据，再清标志**；
  3. `EventBus_Publish(TOPIC_CURRENT_ALARM, &copy)`；
  4. 走现有链路（RTurn → Motor → 仲裁 → GPIO 拉停）。
- 合并语义：主循环未处理期间再次触发 → 标志保持 1，事件合并为一次。下游 RTurn 有锁保护、Motor block 幂等，效果正确（EventBus 本身无去重，已核实 `EventBus.c:148-183`）。
- 原子性：标志/32 位字段在 Cortex-M4 上单次读写原子；用 `volatile` 保证顺序；拷贝事件时数据在 pending=1 期间不会被 ISR 覆盖。

### 5.5 主循环改动点

1. **`ESystem_MainLoop()` 最顶部**（`now-last_loop_time` 门控之后、`Sim_ProcessInput` / `ProcessDeviceUpdates` 之前）：
   - 检查并处理 `g_u8SensorOcPending`（含未校准阶段的提前 return 路径——放在顶部天然覆盖所有路径）；
   - `Sensor_Device_ProcessPendingEvent()` 内部先判断 `EventBus_IsEnabled()`，未使能时保持 pending 不清（防止初始化阶段事件被吞）。
2. **`Sensor_Device_Update()`**：
   - 删除或条件编译关闭旧 `Sensor_CheckOvercurrent()` 调用（避免双检测器重复触发）；
   - 保留 `Sensor_ReadFromAdc` / `Sensor_CalcCurrent` / 校准 / 遥测 / 调试打印。
3. **清除联动**（`Sensor_Device_ClearAlarm` 或故障清除路径）：
   - 现有逻辑不变（清主循环侧 alarm 状态、发布 u8IsActive=0）；
   - **必须删除早退**：现有 `Sensor_Device_ClearAlarm` 开头 `if (!pstcDev->stcAlarmState.u8OvercurrentAlarm) return;`（`dev_sensor.c:651`）在新方案下主循环侧 alarm 状态永不为 1，会导致清除直接空转、ISR 锁存永不复位（保护失效）。必须删除该早退，改为无条件清理。
   - **新增**：同时复位 ISR 状态机（`oc_state = OC_NORMAL`）、清 `g_u8SensorOcPending`（丢弃陈旧触发，避免清除后又被旧 pending 重新加锁）、清主循环 alarm 状态、发布解除事件（保留，目前下游忽略但语义完整）。
   - 该函数是 485 清除链路的现成挂点：`App_FaultHandler.c:202` 已调用，**App_FaultHandler / App_Params 无需改动**。

### 5.6 消隐语义（已确认）

- 消隐期间（`g_u8MotorForwardBlankActive` 或 `g_u8MotorReverseBlankActive` 为 1）：
  - ISR **完全不判定**，并**清空过流状态**（不启动窗口、不置 pending）。
- 消隐结束后：下一个超限采样点才开始 40ms 窗口计时。
- 注意：消隐标志由主循环 `Motor_Update` 清除（`dev_motor.c:1441-1448`）；若主循环卡顿，消隐结束判定同步推迟（当前可接受，已确认）。

## 7. 精度与延迟分析

### 7.1 检测精度

- 判定频率：5kHz（每个 200µs 采样点）。
- 时间戳：Timer6，ADC ISR 内更新，量化 ≤200µs。
- 窗口误差：**±1 个采样周期（±200µs）**，与主循环无关。
- 旧方案 vs 新方案：

| 项 | 旧方案 | 新方案 |
|---|---|---|
| 判定频率 | 主循环 ~1kHz（受调度影响） | 5kHz 固定 |
| 时间基准 | tickTimer 1ms | Timer6 µs（ISR 内更新） |
| 使用数据 | EMA 滤波值 | 原始值（编译期灵敏度换算） |
| 窗口误差 | ±1ms 量化 + 主循环抖动（实测 30~100ms） | ±200µs |
| 毛刺/回落 | 无 | 严格连续（无容忍） |

### 7.2 执行延迟

- 从"窗口满足"到"GPIO 拉停" = 0 ~ 1 个主循环周期（正常 ~1ms；最坏 = 主循环被阻塞时长）。
- 该延迟是**固定、可解释**的，不再造成 30~100ms 的随机波动。
- 若未来要求硬实时停车（主循环卡死也要停），需评估方案三（ISR 直接拉停 + 锁存联动），本设计暂不实施。

## 8. 风险与注意事项

1. **双检测器不能并存**：旧主循环 `Sensor_CheckOvercurrent` 必须关闭，否则一次过流触发两次。
2. **Timer6 初始化顺序**：`Timer6_Timebase_Start()` 由 MotorHall 设备（ID 10）初始化，早于 ADC（ID 11）——必须保持；ADC 中断不得先于 Timer6 启动。
3. **UpdateTimestamp 调用点统一**：从 `motor_hall_update()` 移除或隔离，避免与 ADC ISR 竞争。
4. **主循环卡顿**：影响执行延迟（非检测精度）；标志检查放最顶部可最大限度降低影响。
5. **消隐耦合**：消隐结束依赖主循环清除标志；若未来要求消隐严格计时，需把消隐计时也搬入 ISR/时间戳。
6. **清除联动遗漏**：手动清除若不复位 ISR 锁存，后续过流将不再触发（最重要的隐患）。
7. **EventBus 无去重**：重复发布由 RTurn 锁 + block 幂等兜底；不要依赖 EventBus 本身去重。
8. **uint64 时间戳非原子**：仅 ISR 内读写；主循环调试读取容忍偶发撕裂。

### 调试变量清单（volatile）

- `g_dbg_isr_oc_state`：0=正常 1=计时中 2=已触发
- `g_dbg_isr_oc_start_us`：窗口起始 µs
- `g_dbg_isr_oc_elapsed_us`：当前已计时 µs
- `g_dbg_isr_oc_window_us`：锁存窗口 µs
- `g_dbg_isr_oc_cur_ma`：最近一次 ISR 换算电流
- `g_u8SensorOcPending`：待处理标志（Keil Watch 可观察）

## 12. 关键要点汇总（34 条，终版 2026-08-05）

> 以下 34 条为本次过流检测优化从问题到实施的全部重点，与正文各节一致；如有出入，以本节为准。
> 注：2026-08-06 的增量修改（采样 200µs、回落容忍当前 0、反转屏蔽 50ms、窗口默认 10ms、调试测量）见 §13，与本节条目如有出入以 §13 为准。

### A. 问题背景

1. **实测现象**：过流阈值 1.1A、判定窗口 40ms，理论上连续超限 40ms 触发；示波器实测在 **30ms ~ 100ms 之间波动**。
2. **根因结论**：波动不是“40ms 计时本身”的问题，而是**判定时机依赖主循环轮询 + 毫秒量化 + EMA 滤波滞后 + 噪声提前启动计时**。
3. **已排除因素**：启动消隐与实测波动无关（测量场景不在堵转位置启动），但实现上仍需处理其语义。

### B. 现状架构分析（三层电流采样链）

4. **采样**：ADC 硬件 200µs（5kHz），Timer0_1 CH_B → AOS → ADC1 单次转换。
5. **Adc.c 适配层（ISR）**：EOCA 中断里更新 `u16LatestValue`，并调用已注册的 `pfnCallback(value, channel)`。
6. **dev_adc 设备层**：ISR 里 `OnDataReady` 写环形缓冲；主循环 Update 批量取出做 **EMA(α=0.4) 滤波**，缓存 `u16VoltageMv`。
7. **dev_sensor 设备层**：主循环 Update 读滤波值 → 算电流（mV-零点-偏移）×1000/264 → **时间窗口模式**（`nbDelay` + `tickTimer` 毫秒）。
8. **下游链路**：`TOPIC_CURRENT_ALARM` → RTurn（锁方向/报故障/双向发布）→ `TOPIC_OVERCURRENT_FWD/REV` → Motor 插 block → 仲裁 → GPIO 拉停（PB8/PB9 置高，GPIO 模式）。
9. **误差拆解公式**：`T_total = 起点滞后 + 滤波滞后 + 40ms(毫秒量化) + 终点滞后 + 执行`（起点/终点各 0~1 个主循环周期）。
10. **提前触发（30ms）原因**：噪声/毛刺让计时起点早于真实越限（无毛刺剔除），或零点偏置导致计算电流偏大。
11. **延迟触发（100ms）原因**：主循环被 RS485/Modbus/打印等拖慢时起点+终点滞后同时放大；电流在阈值附近抖动时任一非超限采样点都会 `nbDelay_Stop` 清零窗口。

### C. 新方案（方案二：ISR 判定 + 主循环发布）

12. **核心思路**：把过流判定搬进 **ADC 中断**，用 **Timer6 微秒时间戳**精确计时；主循环只负责把事件发布到现有链路（下游 RTurn/Motor/仲裁/GPIO **零改动**）。
13. **候选方案对比**：① ISR 直接 EventBus 发布（ISR 过重、有并发风险）② ISR 置标志 + 主循环发布（**选定**）③ ISR 直接 GPIO 拉停（最快但绕开业务逻辑）。
14. **Timer6 时间戳**：PCLK0=200MHz /64 → 3.125MHz（0.32µs/计数），16 位每 ~20.97ms 回绕；原 `GetTimestamp()` 只有 ~1ms 精度（仅 `motor_hall_update` 主循环调用 `UpdateTimestamp`），改为 **ADC ISR 每 200µs 调用一次** → 量化 ≤200µs、uint64 无溢出、回绕自动处理，**40ms~65535ms 窗口均兼容**。
15. **判定数据**：用**原始 ADC 值**（无 EMA 滞后），ISR 内纯整数运算（raw→mV→mA）。
16. **严格连续 + 回落容忍（宏可配）**：`SENSOR_OC_DROP_TOLERANCE_US` 当前 0=严格连续（任一采样点低于阈值即清零重计）；>0 时允许回落 <N ms 不清零（free-run）；**无回差**（已确认）。
17. **参数不写死**：窗口/阈值从 `stcConfig`（寄存器 0x271E/0x2716，485 可配）；**进入过流时锁存**，本次过程不受运行中改参影响，下次过流才生效。
18. **滤波预留**：默认直通原始值；预留 `SENSOR_OC_FILTER_MA4`（4 点滑动平均 ≈0.8ms）接口，暂未启用。
19. **消隐语义**：消隐期间 ISR **完全跳过判定并清空窗口状态**，消隐结束才重新开始 40ms 计时。
20. **防重复与重新武装**：`OC_TRIGGERED` 锁存防止同一次持续过流重复发布；**电流回落后自动回到正常**（下次可直接触发）；手动/485 清除作为“电流仍超限”时的强制复位兜底。
21. **交接协议**：ISR **先写缓存、再置 pending**（仅 pending==0 时写）；主循环**先拷贝、再清标志**；粘性标志，未处理期间多次触发合并为一次（EventBus 无去重，但 RTurn 锁 + block 幂等保证效果正确）。
22. **主循环处理**：`ESystem_MainLoop()` 顶部（1ms 门控后、RS485/Modbus 前）调用 `Sensor_Device_ProcessPendingEvent()`；**EventBus 未使能前保持 pending** 不清，防止初始化阶段事件被吞。
23. **清除联动**：`Sensor_Device_ClearAlarm` **删除早退**（否则 485 清除会空转、ISR 锁存永不复位），改为无条件复位 ISR 状态 + 清 pending；`App_FaultHandler.c:202` 已有调用点，**无需改动**。
24. **告警状态来源切换**：`CMD_SENSOR_GET_ALARM_STATUS` 改为读 ISR 状态（`OC_TRIGGERED` 或 pending），**RTurn 轮询备份路径恢复可用**。
25. **旧判定关闭**：`Sensor_CheckOvercurrent` 相关函数用 `#if !SENSOR_OC_ISR_DETECT_ENABLE` 包裹，**可一键回退旧方案**。
26. **初始化顺序依赖**：Timer6 由 MotorHall（ID 10）先于 ADC（ID 11）启动；`UpdateTimestamp` 调用点统一到 ADC ISR，**移除 `motor_hall_update` 中的调用**（霍尔计数走 `GetDelta()` 裸计数器，不受影响；`GetTimestamp` 反而从 1ms 精度提升到 200µs）。

### 13.2 设计决策更新

1. **采样间隔**：发现原 `Adc.h` 实际为 1000U（1ms），已改回 200U（200µs/5kHz）；本方案所有精度前提以 200µs 为准。
2. **回落容忍**：新增宏 `SENSOR_OC_DROP_TOLERANCE_US`（free-run 语义：回落 <N ms 不清零、窗口墙钟继续走；任一低于阈值采样点立即清零为 0 值行为）。当前按用户要求置 **0（严格连续）**，现场可按需改回 2000U（2ms）等。
3. **启动屏蔽**：关窗（反转）方向 `MOTOR_REVERSE_BLANK_MS` 0→50ms；正转保持 50ms。启动屏蔽期间 ISR 完全跳过判定。
4. **过流窗口默认**：`PARAM_DEFAULT_CURRENT_DETECT_MS` 40→10ms（**仅默认值**；若 Flash 已存 40，需 485 写 `0x271E=10` 或恢复出厂参数才生效）。
5. **调试测量**：`[OC] trigger_us / estop_us / elapsed / reset_cnt`，Timer6 累加器 200µs 量化。实测 `elapsed` 多为 0——这是量化假象（T0/T1 落在同一 200µs 网格），不代表零延迟；用户接受 200µs 精度，未采用裸计数器方案。
6. **优化方向**：停住电流 ≈ 阈值 + 电流上升速率 × 确认窗口。实测：40ms 窗口时停住平均电流 ~1.4A（原方案 ~2.0A）；目标接近 1.1A → 采用“**启动屏蔽（50ms 正/反转）+ 短窗口（默认 10ms）**”。备选：双阈值快速线、di/dt 上升速率检测（均未实施）。

### 13.3 待复测

- 正常关窗不误动（启动尖峰被 50ms 屏蔽挡住）；
- 关窗堵转停住平均电流（目标 ~1.15~1.2A）；
- `[OC]` 日志 `reset_cnt`：若 >0 说明回落超过当前容忍（0=严格连续），需把 `SENSOR_OC_DROP_TOLERANCE_US` 调回非 0；
- 窗口值可经 485 写 `0x271E`（10ms/20ms/5ms）现场调优。
