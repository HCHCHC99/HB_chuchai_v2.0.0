# 过流优化 0807

> 日期：2026-08-07　分支：`restore-b948c7e`　工程：HB_chuchai_v2.0.0（HC32F460）
> 状态：采样/滤波/调度已提交（`1da9375`、`c708086`）；**窗口占比判据（20%）与文档为本次提交**

## 1. 背景与目标

- 工况：**直流有刷电机关窗器**，通过**堵转电流**判断窗户是否关紧。
- 问题：直流有刷电机电流存在周期性抖动（实测周期约 **2ms**），且**堵转时平均电流越大，抖动幅值越大**：
  - 阈值 1.1A 时：停车前瞬间抖动峰值约 1.3A；
  - 阈值 1.6A 时：停车前瞬间约 1.6A ~ 2.7A（平均约 2.15A）。
- 目标：**电机在“电流平均值 = 设定阈值”时停住**（阈值 1.1A 就应在平均 1.1A 时停车）。

## 2. 当前策略

### 2.1 ADC 采样
- 采样周期：**50µs（20kHz）**，宏 `ADC_SAMPLE_INTERVAL_US = 50U`（`Adp/Adc.h`）。
- ADC1 SEQ_A 由 Timer0（TMR0_1 CH_B）硬触发，EOCA 中断逐通道读取。

### 2.2 均值滤波：固定 N 点滑动平均
- 窗口：**120 点 = 6ms = 3 个完整纹波周期**（整数倍周期 → 精确抵消纹波，与纹波幅值无关；`Dev/dev_adc.h` `ADC_MEAN_WINDOW_SAMPLES = 120U`）。
- EOCA 中断（20kHz）里**逐样本**维护滑动窗口和：`sum = sum - 最旧 + 最新`（`Dev/dev_adc.c` `ADC_Device_OnDataReady`）。
- 1ms 中断里取 `sum / 120` 作为平均值（`Dev/dev_adc.c` `ADC_Device_UpdateFilter`）。
- 环形缓冲（32 点）**保留仅作调试**（`ReadBatch` 用），**不再是均值数据源**。

### 2.3 消费与调度（单消费者）
- 环形缓冲 / ADC 更新**只由 1ms 中断**（`TMR0_Unit2_1msTask`）消费。
- **主循环 ADC update 全程禁用**：`ESystem_Init` 中 `SetDeviceUpdateIntervals()` 在 `DeviceManager_EnableAllUpdate()` **之后**执行，保证 `ID_ADC_CURRENT / ID_ADC_VOLTAGE` 的 `DisableUpdate` 不被覆盖（`App/App_Motor_Project.c`）。
- 传感器零位校准：**EOCA 采集保持开启**；校准读取 1ms 中断产出的均值缓存（`Device_Read`）；主循环只保留 `Sensor_Device_Update` 校准状态机。

### 2.4 过流判定：窗口占比判据（泛化的平均值判据）
- 平均值 ≈ 窗口样本的 **50% 线**；现把该百分比**泛化**为可配置值。
- 判定值：**120 点滑动窗口**，每 **1ms** 刷新一次判定。
- 触发条件：**窗口内 ≥ 阈值的样本占比 ≥ `OVERCURRENT_WINDOW_PERCENT`（默认 20%）**，且持续 `current_detect_ms = 1ms` → 判定过流（P=50 时约等于原均值判据）。
- 阈值：`current_upper_limit`，默认 **1100mA**（Modbus `0x2716`）；触发点 = 阈值 + 滞回（当前 0）。
- 清除方式：**手动**（`OVERCURRENT_CLEAR_MANUAL`）；释放窗口 `current_release_ms` 默认 200ms；释放侧仍用均值（`u8IsNormal`）。
- 触发后链路：1ms ISR 置 pending → 主循环 `ProcessSensorPendingEvents` 发布 `TOPIC_CURRENT_ALARM` → `Motor_OnCurrentAlarm` → 仲裁决策 → 立即停车。

## 5. 调参说明

- **窗口换算**（50µs 采样下）：`点数 = 纹波周期(ms) × 20 × 周期数`，必须取**整数倍周期**才能精确抵消纹波。
  - 2ms 周期：40 点（1 周期）/ 80 点（2 周期）/ **120 点（3 周期，当前）**；周期数越多越平滑，但滞后越大。
- **`OVERCURRENT_WINDOW_PERCENT`**：窗口占比判据的百分比。50≈原均值判据；20 表示窗口内两成样本过线即判定（实测效果良好，会比均值判据更早触发）。可用 JScope 观察 `g_dbg_sensor_win_over_cnt / g_dbg_sensor_win_over_pct`。
- **`current_detect_ms`**：当前 1ms；窗口占比已平滑，1~2ms 足够，越小停车超调越小。
- **阈值**：默认 1100mA；想“停车即平均=阈值”时，阈值直接设为目标平均电流。
- 若高阈值（如 1.6A）下停车点仍偏高：优先把 `current_detect_ms` 保持 1；或接受少量超调——**堵转电流爬升的机械延迟无法被滤波消除**。

## 6. 实测现象与验证方法

- 修改前现象（记录）：纹波周期 2ms；1.1A 阈值停车前峰值约 1.3A；1.6A 阈值停车前 1.6~2.7A（平均约 2.15A）。
- 验证：
  1. Keil 重新编译烧录；
  2. JScope 观察 `g_dbg_current_filtered_ma`：应**平滑无 2ms 纹波**；同时可用 `g_dbg_sensor_win_over_cnt / g_dbg_sensor_win_over_pct` 观察窗口内超阈值样本数与占比；
  3. 分别用 1.1A / 1.6A 阈值堵转，对比**停车瞬间平均值**是否≈阈值。
- 注意：纹波周期可能有波动，若实测周期变化，按第 5 节公式重新调整 `ADC_MEAN_WINDOW_SAMPLES`。
