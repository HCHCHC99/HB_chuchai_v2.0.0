# 绝对角度功能说明

## 一、设计背景

现有实时角度（0x2731）依赖关窗过流校准，校准前角度无效，且掉电丢失零点。绝对角度功能在此基础上新增：

- **独立于校准**：无论是否完成关窗过流校准，绝对角度都能正常追踪
- **掉电不丢零点**：用户设定的绝对零点通过 Flash 持久化，上电自动恢复
- **欠压自动保存**：检测到欠压时自动将当前位置保存到 Flash，掉电后上电恢复
- **全部操作仅需单条 Modbus 指令**

---

## 二、数据模型

### 核心公式

```
绝对角度偏移 = RAM实时偏移 = 相对绝对零点的角度差 (单位 0.1°)

每 1ms 更新一次:
  delta = g_s32HallPulseAccum(当前) - s_last_accum(上次)
  s_abs_offset_x10 += delta × 3600 / (极对数 × 霍尔数 × 2 × 减速比)
```

### 关键变量

| 变量 | 存储位置 | 说明 |
|------|---------|------|
| `s_abs_offset_x10` | RAM | 实时偏移，每 1ms 更新，不掉电保留 |
| `s_last_accum` | RAM | `g_s32HallPulseAccum` 的上次快照 |
| `g_AbsAngle.abs_offset_x10` | Flash（扇区55） | 已保存的偏移值，掉电不丢 |
| `g_AbsAngle.goto_zero_thresh_x10` | Flash（扇区55） | 回零阈值 (0.1°)，默认1，范围0~200 |

### 方向约定

```
开窗(正转/FWD) → g_s32HallPulseAccum 增加 → 偏移增大 (正值方向)
关窗(反转/REV) → g_s32HallPulseAccum 减少 → 偏移减小 (负值方向)

偏移 > 0: 当前位置在绝对零点正方向（开窗超出的角度）
偏移 < 0: 当前位置在绝对零点负方向（关窗超出的角度）
```

### 程序流程

```
上电启动:

    → Hardware_Init()
    → ...
    → ESystem_Init()
      → Param_Init(&g_AppParam)   // 加载常规参数

主循环 (每 1ms):
  while(1)
    → ESystem_MainLoop()
      → ProcessDeviceUpdates()    // MotorHall update → g_s32HallPulseAccum 更新
      → RunAngle_Update()         // delta → s_abs_offset_x10 更新

```

### 存储架构

```
Flash 扇区 55 (独立于常规参数扇区 62-56):
  使用 param_manager 多实例引擎
  结构体 AbsAngleRecord_t (32字节/条)
  魔数: 0xAB5AAB5A / 0xBA5ABA5A (独立, 防串扰)
  顺序追加写入 + CRC32 校验 + 磨损均衡
```

## 四、Modbus 寄存器

| 寄存器 | 地址 | 读写 | 数据类型 | 说明 |
|--------|------|------|----------|------|
| RAM偏移_LO | 0x2721 | R | int32 低16位 | 实时绝对角度偏移 (0.1°) |
| RAM偏移_HI | 0x2722 | R | int32 高16位 | |
| Flash偏移_LO | 0x2723 | R | int32 低16位 | Flash 中已保存的偏移 (0.1°) |
| Flash偏移_HI | 0x2724 | R | int32 高16位 | |
| 绝对角度指令 | 0x2725 | W | uint16 | 命令寄存器 (见下表) |
| 回零阈值 | 0x2726 | R/W | uint16 | 回零停止阈值 (0.1°)，默认 1，范围 0~200 |

### 0x2725 指令表

| 写入值 | 操作 | 说明 |
|--------|------|------|
| `00 00` | 设零点并保存 | RAM=0, Flash=0, 写入Flash |
| `00 01` | 回到绝对零点 | 自动识别方向, 转动到阈值内后 ESTOP |
| `00 02` | 保存 RAM 偏移到 Flash | 固化当前偏移, 掉电后上电恢复 |
| `00 03` | 设当前位置为绝对零点 | RAM=0, Flash=0, 写入Flash（行为与 `00 00` 相同） |

> **注意**：`00 00` 和 `00 03` 在实际代码中走同一分支，行为完全一致（均归零并保存到 Flash）。

### 0x2726 回零阈值

| 操作 | 指令 | 说明 |
|------|------|------|
| 读 | `01 03 27 26 00 01` | 返回 uint16 (0.1°) |
| 写 | `01 06 27 26 00 0A` | 设 1.0° (值=10), 限幅 0~200, 写Flash, 热重载立即生效 |

### Modbus 读写调度逻辑

绝对角度寄存器的读写有两条独立的路径，与常规参数（0x2710~0x271E）分离：

**读路径（功能码 0x03）** — `App_Modbus.c` → `Param_ReadByReg()` (App_Params.c)

```
Modbus 0x03 请求
  → Modbus_HandleReadHolding()
    → Param_ReadByReg(regAddr, &value)
        ├─ 0x2721/0x2722 → RunAngle_GetOffset_x10()     // RAM 实时偏移 int32
        ├─ 0x2723/0x2724 → RunAngle_GetFlashOffset_x10() // Flash 已保存偏移 int32
        └─ 0x2726        → g_AbsAngle.goto_zero_thresh_x10
```

**写路径（功能码 0x06/0x10）** — `App_Modbus.c` 直接拦截，不经过 `Param_WriteByReg()`

```
Modbus 0x06/0x10 写请求
  → Modbus_HandleWriteSingle() / Modbus_HandleWriteMulti()
      │
      ├─ regAddr == 0x2725 → RunAngle_Cmd(value)         // 直接拦截，不走 Param_WriteByReg
      ├─ regAddr == 0x2726 → RunAngle_SetThreshold(value) // 直接拦截，不走 Param_WriteByReg
      │
      └─ 其他寄存器       → Param_WriteByReg()           // 常规参数 Flash 扇区 62-56
```

> 关键设计：绝对角度拥有独立的 Flash 扇区（55）、独立的 `param_manager` 实例、Modbus 层直接拦截写入。与常规参数的存储和写入路径完全隔离。

## 五、操作指南

### 首次使用 (安装后)

```
1. 电机转到想要的"绝对零点"位置
2. 发: 01 06 27 25 00 00    → 设零点并保存
   此时 0x2721/0x2722 读回 0x00000000
```

### 正常运行中读取角度

```
读 RAM 实时偏移:
  发: 01 03 27 21 00 02
  回: 01 03 04 XX XX XX XX crc_l crc_h
  解析: 4字节拼为 int32, ÷10 = 度数 (正=开窗方向, 负=关窗方向)

读 Flash 已保存偏移:
  发: 01 03 27 23 00 02
  解析同上
```

### 保存到 Flash

**手动保存:**

```
发: 01 06 27 25 00 02    → 保存到 Flash
下次上电后自动恢复
```

**自动保存 (欠压触发):**

当系统检测到欠压时，`App_FaultHandler` 会自动调用保存逻辑，将当前 RAM 偏移值写入 Flash。用户无需手动操作。上电后自动恢复掉电前的位置。

### 回零

```
1. 可选: 设置回零阈值  01 06 27 26 00 0A  → 设 1.0°
2. 发: 01 06 27 25 00 01                  → 自动转动到零点
   电机自动识别方向 → 转动 → 到达后 ESTOP 停止
```

### 回零阈值管理

```
读当前阈值: 01 03 27 26 00 01  → 返回 uint16 (0.1°)
设阈值:     01 06 27 26 xx xx  → 写入 0~200, 热重载立即生效
```

## 六、回零逻辑详解

### 调用路径

```
Modbus 写 0x2725=1 (00 01)
  → App_Modbus.c 拦截
    → RunAngle_Cmd(ABS_CMD_GOTO_ZERO)
      → RunAngle_GotoZero()
        → 判断偏移方向，发布 FWD/REV 事件
        → 设置 s_goto_zero_active = true

每 1ms (RunAngle_Update):
  检查 s_goto_zero_active:
    条件1: |偏移| ≤ 阈值(0x2726) → 发 ESTOP, 结束
    条件2: 偏移符号翻转 (越过零点) → 发 ESTOP, 结束
```

### 方向判定

```
发 0x2725=1:
  偏移 > +阈值 → 发 REV (关窗方向) 指令
  偏移 < -阈值 → 发 FWD (开窗方向) 指令
  偏移在 ±阈值 内 → 无需转动, 直接结束
```

### 回零阈值

- 可通过 0x2726 寄存器配置，默认 1 (0.1°)
- 范围 0~200 (0° ~ 20.0°)
- 写入后立即生效 (热重载)，无需复位

### 回零中断

回零过程中可随时通过 Modbus 发 ESTOP (0x2720 bit2=1) 或过流保护中断转动。

### 回零后继续使用

回零完成后发 ESTOP 停转，用户可正常发送 FWD/REV 指令继续操作。

## 八、与实时角度 (0x2731) 的区别

| 维度 | 实时角度 (0x2731) | 绝对角度 (0x2721) |
|------|------------------|-------------------|
| 零点来源 | 关窗过流校准 | 用户手动设定 + 过流自动清零 |
| 校准前有效 | 否 (返回0) | 是 |
| 掉电保留 | 否 | 是 (Flash + 欠压自动保存 + 过流自动保存) |
| 更新频率 | 1ms (校准后) | 1ms (始终) |
| 数据类型 | int16 (0.1°) | int32 (0.1°) |
| 用途 | 限位、过流判断 | 位置记忆、回零 |

两者独立运行，互不影响。绝对角度的脉冲追踪与 dev_rturn 校准状态无关。**新增强制同步点：每次关窗过流触发 dev_rturn 校准时，自动将绝对角度 RAM 和 Flash 同时归零（详见第九章）。**

## 九、关窗过流自动校准绝对零点

### 9.1 设计动机

在实际工况中，电机持续运行可能导致绝对角度因脉冲累积误差而产生缓慢漂移。关窗到底的机械位置是系统中最可靠的物理参考点——每次关窗时，机械位置确定，没有"上次和这次位置不同"的问题。因此，利用每次关窗过流校准事件自动归零绝对角度，是最自然的消偏方案。

### 9.2 方案选择：每次关窗 vs 仅首次校准

| 维度 | 方案A：每次关窗都触发 | 方案B：仅首次校准（u8Calibrated 0→1） |
|------|----------------------|---------------------------------------|
| 触发条件 | 4个校准点全部触发 | 仅校准点1/3（首次校准时） |
| 每通电周期触发次数 | 多次 | 1次 |
| Flash 写入 | 每次关窗写一次 | 仅首次写一次 |
| 解决累积偏移 | ✅ 彻底解决 | ❌ 首次后的偏移仍会累积 |
| Flash 寿命影响 | 每天50次关窗可用160年 | — |

**选择方案A**。Flash 扇区55单扇区可写入 292万次（292条/扇区 × 10,000次擦除），完全不是瓶颈。关窗校准是低频机械事件（~20-40ms Flash 写入不影响实时控制），且每次关窗都是可靠的机械零点参考。

### 9.3 实现概述

新增 `RunAngle_OnCalibration()` 函数，由 `dev_rturn` 在每次将 `g_s32HallPulseAccum` 归零时调用。涉及3个文件的修改：

| 文件 | 修改 |
|------|------|
| `Utils/App_RunAngle.h` | 新增 `void RunAngle_OnCalibration(void);` 声明 |
| `Utils/App_RunAngle.c` | 新增 `RunAngle_OnCalibration()` 实现 |
| `Dev/dev_rturn.c` | 新增 `#include "App_RunAngle.h"` + 4个校准点各新增1行调用 |

### 9.4 RunAngle_OnCalibration() 函数逻辑

```c
void RunAngle_OnCalibration(void)
{
    __disable_irq();
    s_abs_offset_x10 = 0;                    // ① RAM 归零
    s_last_accum = g_s32HallPulseAccum;      // ② 同步脉冲基线（accum 已被 dev_rturn 清零）
    __enable_irq();

    g_AbsAngle.abs_offset_x10 = 0;           // ③ Flash 镜像归零
    Param_Save(&s_Config, &s_Runtime);       // ④ 顺序追加写入 Flash 扇区55

    MAIN_D("[ABSA] Calibration zero: RAM=0, Flash=0\r\n");
}
```

**三件事依次执行**：
1. RAM 偏移归零 + 脉冲基线同步（关中断保护，防止 motor_hall_update 中断干扰）
2. Flash 结构体字段归零
3. 顺序追加写入 Flash（Param_Save：计算 CRC → 写入 → 校验 → 递增序列号 → 推进写指针）

**为什么需要同步 s_last_accum**：`dev_rturn` 将 `g_s32HallPulseAccum` 清零后，若 `s_last_accum` 仍保留旧值，下一次 `RunAngle_Update` 将计算出巨大负 delta（`0 - 旧值 = -几千脉冲`），导致 `s_abs_offset_x10` 跳变。同步后 `delta = 0 - 0 = 0`，后续追踪正常。

### 9.5 dev_rturn.c 中的 4 个调用点

`dev_rturn` 校准将 `g_s32HallPulseAccum = 0` 的时机分两条路径、四种场景：

```
RTurn_UpdateAngle()（轮询路径，每~50ms）
  │
  ├─ 校准点1 (line ~175)：主动检查过流 + 反转方向
  │    首次校准（u8Calibrated = 1）+ 之后每次关窗都触发
  │
  └─ 校准点2 (line ~234)：锁释放后重新检查 + 反转方向 + 已校准
       仅重复校准（不改变 u8Calibrated）

RTurn_HandleOvercurrent()（EventBus 路径，过流事件驱动）
  │
  ├─ 校准点3 (line ~351)：限位触发 + 未校准 + 反转方向
  │    首次校准（u8Calibrated = 1）
  │
  └─ 校准点4 (line ~374)：限位触发 + 已校准 + 反转方向
       仅重复校准（不改变 u8Calibrated）
```

**每个校准点的代码位置**（均在 `g_s32HallPulseAccum = 0;` 之后）：

```c
// 校准点1：轮询路径，首次+重复校准
if (u8CheckDir == RTURN_DIR_REVERSE) {
    g_s32HallPulseAccum = 0;
    pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
    if (!pstcDev->u8Calibrated) {
        pstcDev->u8Calibrated = 1;
    }
    RunAngle_OnCalibration();  // ← 新增
}

// 校准点2：轮询路径，锁释放重检，仅重复校准
if (u8DesiredRTurnDir == RTURN_DIR_REVERSE) {
    if (pstcDev->u8Calibrated) {
        g_s32HallPulseAccum = 0;
        pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
        RunAngle_OnCalibration();  // ← 新增
    }
}

// 校准点3：EventBus 路径，首次校准
g_s32HallPulseAccum = 0;
pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
pstcDev->u8Calibrated = 1;
RunAngle_OnCalibration();  // ← 新增

// 校准点4：EventBus 路径，重复校准
pstcDev->fCurrentAngle = pstcDev->stcConfig.fMinAngle;
g_s32HallPulseAccum = 0;
RunAngle_OnCalibration();  // ← 新增
```

### 9.6 主循环中的执行顺序

```
ESystem_MainLoop() (每 1ms):
  │
  ├─ ProcessDeviceUpdates()
  │     │
  │     ├─ MotorHall update       → g_s32HallPulseAccum 增量更新
  │     ├─ dev_rturn update       → 可能触发校准，清零 g_s32HallPulseAccum
  │     │                              └─ RunAngle_OnCalibration()
  │     │                                    ├─ s_abs_offset_x10 = 0
  │     │                                    ├─ s_last_accum = 0（同步）
  │     │                                    └─ Param_Save → Flash
  │     └─ 其他设备 update
  │
  └─ RunAngle_Update()            → 读 accum，计算 delta
        delta = 0 - s_last_accum = 0 - 0 = 0  ✅ 不产生错误偏移
```

关键：`ProcessDeviceUpdates()` 中 dev_rturn 先于 `RunAngle_Update()` 执行。`RunAngle_OnCalibration()` 在 dev_rturn 校准路径中同步了 `s_last_accum`，确保后续 `RunAngle_Update` 计算 delta 时基线一致。

### 9.7 操作流程示例

```
通电 → 开窗到任意位置 → 读 0x2721/0x2722: 0x00001234 (46.6°)
  │
  └─ 关窗到底 → 电机堵转 → 过流检测 → dev_rturn 校准
        │
        └─ RunAngle_OnCalibration()
              ├─ RAM 偏移 → 0
              └─ Flash 偏移 → 0
        │
        └─ 读 0x2721/0x2722: 0x00000000 ✅
           读 0x2723/0x2724: 0x00000000 ✅
  │
  └─ 再次开窗到一半 → 读 0x2721/0x2722: 0x000009C4 (25.0°) ✅ 从零追踪
  │
  └─ 再次关窗到底 → 过流校准 → 绝对角度再次归零 ✅ 不累积误差
```

### 9.8 与手动设零点的关系

- 手动设零点（0x2725=0x0003）和"设零点并保存"（0x2725=0x0000）在代码中走同一分支，均执行 RAM=0 + Flash=0 + 写入Flash。过流自动清零也调用相同的底层机制
- 两者互不冲突：用户可随时手动设零点覆盖自动值，下次关窗过流会再次自动归零
- 如果用户需要"绝对零点在某个特定位置而非关窗极限位置"，应在设备安装后手动设零点，日常使用中的关窗过流会自动将零点拉回关窗极限位置
- 若需禁用自动清零行为，删除 `dev_rturn.c` 中 4 处 `RunAngle_OnCalibration()` 调用即可
