# 广播分配 ID 方案说明

> 日期：2026-08-16　分支/工程：HB_chuchai_v2.0.0（HC32F460）
> 状态：**方案讨论稿**（尚未实现、未提交），记录当前讨论结论与待确认项

## 一、需求背景

- 设备默认 Modbus 地址为 1（`REG_NODE_ID (0x2710)`），并支持指令修改 ID。
- 客户需求：多台设备挂在同一条 Modbus RTU 总线上时，希望**发一条广播指令就能让多台设备自动分配出不重复的 ID**。
- 难点：设备初始地址都是 1，主机无法对其中某一台单独寻址，只能广播；而多台同时应答必然在 RS485 半双工总线上碰撞。

## 二、设计约束（用户确认）

1. 分配耗时多久都没关系。
2. 原则：从机不能主动发消息，只能主机来问（标准 Modbus 主从）。
   - **特例**：允许从机之间利用总线进行信息交互，**仅限于“设定 ID”这一个特殊处理场景**。
3. 主机发的指令尽量简短，主机做的事情尽量简洁，理想情况只需三条广播：
   - **搜集信息**
   - **分配ID**
   - **查看分配ID情况**（检查 ID 分配是否 OK）
4. 不接受“主机广播询问后得知从机 UID，再针对 UID 逐台分配 ID”这类方案（主机太麻烦）。
5. 分配失败：从机保留原地址 1，不主动告警（遵循 Modbus 主从，从机不能主动发）；主机可通过“查看分配ID情况”发现重复/缺失。
6. 总线规模：单总线最大 248 台，实际可能约 30 台；波特率 9600。
7. 只有收到“开始分配”广播才参与分配，正常工作时不受影响。

## 三、硬件能力调研结论（HC32F460）

### 3.1 真随机数发生器 TRNG —— 存在 ✅
- 驱动：`HC32F460_DDL_Rev3.3.0\drivers\hc32_ll_driver\inc\hc32_ll_trng.h` 与 `src\hc32_ll_trng.c`
- 原理：硬件噪声捕获（移位寄存器，可配 32/64/128/256 次），双 32 位数据寄存器 `DR0/DR1`，驱动做 `XOR 0x55555555` 增强，`TRNG_Init()` 自动丢弃前 10 组数据。
- API：
  - `TRNG_Init(u32ShiftCount, u32ReloadInitValueEn)`
  - `TRNG_GenerateRandom(uint32_t *buf, uint32_t len)`（一次取多组 32 位）
  - `TRNG_GetRandom(uint32_t *buf, uint8_t len)`（len≤2）
  - `TRNG_Cmd / TRNG_Start / TRNG_DeInit`
- 寄存器：`CM_TRNG` @ `0x40041000`；时钟门控在 **FCG0 bit22**（`FCG0_PERIPH_TRNG` / `PWC_FCG0_TRNG`）。
- 使用前需改动：
  - `template\source\hc32f4xx_conf.h`：`LL_TRNG_ENABLE` 当前为 `DDL_OFF`，需改 `DDL_ON`；
  - 使用前需 `FCG_Fcg0PeriphClockCmd(FCG0_PERIPH_TRNG, ENABLE)`（驱动不负责开时钟门）。
- 特性：真随机（基于物理噪声）→ **同一时刻多台设备各自取值互不相关**，满足“多台之间同一次申请随机数不一致”的要求。

### 3.2 芯片唯一号 UID —— 存在，但最终方案不依赖 ✅（备选信息）
- 寄存器：`CM_EFM->UQID0 / UQID1 / UQID2`（EFM 基址 `0x40010400`，只读 `__I`，共 96 位）
- 函数：`EFM_GetUID(stc_efm_unique_id_t*)`（`hc32_ll_efm.h:467`），`LL_EFM_ENABLE` 当前已是 `DDL_ON`。
- 结论：UID 可作为“唯一令牌”的备选来源，但当前方案采用纯 TRNG，不依赖 UID。

## 四、方案演进与取舍（简记）

1. **最初思路（用户提出）**：广播后各从机用随机数设定回复时间区间，第一台回复，其余等待其分配完成，再轮到下一台。
2. **第一版细化（TRNG 令牌 + 逐轮分配）**：随机退避 + 64 位令牌 + 主站逐轮广播分配、单播读校验。
   - 问题：主站要记令牌、逐台分配 → 违反“主机最简”约束；且 30 台、9600bps 下“第一台先回复”碰撞率高。
3. **第二版（收集-分配两阶段）**：主站整窗收集多台令牌再逐台分配。
   - 问题：主机仍要处理每台令牌 → 同样违反约束。
4. **当前方向（从机自协商，主机只发 3 条广播）**：把“谁拿几号”的分配智能全部放到从机之间（用户允许的特例），主机不接触 UID/令牌。**详见第五节。**

## 五、当前方案（推荐方向）

### 5.1 三条广播的职责

| 广播 | 主机动作 | 从机动作 |
|---|---|---|
| 搜集信息 | 发完闭嘴，等总线安静（如 2~3 秒无有效帧） | 无 ID 从机在总线上**互相协商**，各自取得连续唯一暂定编号 1..N（唯一允许从机自发消息的特例） |
| 分配ID | 广播后等待片刻 | 已取得暂定编号的从机写入 Flash、切换到新地址，此后变回标准 Modbus 从机 |
| 查看分配ID情况 | 广播后按时间槽监听、数回包 | 每个从机按自己的 ID k 延时 k×T 回一短帧（ID 唯一→时槽唯一→不碰撞） |

### 5.2 从机自协商算法（claim + 计数 + 随机退避 + 回环校验）

所有无 ID 从机维护计数器 `c = 已听到的有效编号数`（初始 0），规则：

1. 听到别人喊“我占 X 号” → `c = X`；
2. 自己 TRNG 随机退避到点、且总线空闲 → 喊“我占 c+1 号”；
3. 喊完看**回环**（自己发自己收）：CRC 正确且无叠加 → 正式定为 c+1 号、退出协商；回环异常（碰撞）→ 换新随机数重试。

一致性依据：RS485 共享总线，**成功的喊话所有从机都能听到，撞坏的喊话所有从机都听不到** → 各从机对“已占编号”的认知一致 → 结果编号 1..N 连续唯一。

#### 3 台设备示例
1. A/B/C 均无 ID，收到“搜集信息”，初始 c=0；
2. A 退避 30ms 喊“占 1 号”，回环干净 → A=1 退出；
3. B 听到 1 号（c=1），80ms 喊“占 2 号”，干净 → B=2；
4. C 听到 1、2 号（c=2），200ms 喊“占 3 号” → C=3；
5. 总线安静 → 主机发“分配ID”→ 写 Flash、切地址 → 发“查看”→ 1/2/3 号槽各回一帧 → 确认。

#### 碰撞处理示例
A(30ms)、B(35ms) 同时喊 1 号 → 两帧叠加、回环乱码 → 都重试（c 仍 0）→ 例如 B 先喊成 1 号，A 听到后改喊 2 号 → 最终 1/2/3。

### 5.3 查看分配ID情况（主机侧检查）

- 主机发“查看”后监听 `最长等待 = 最大地址数 × T`（T≈2~3 倍帧时长；9600bps 建议约 30ms；247 号 ≈ 7s）。
- 判定：
  - 某号无回包 → 缺失（设备未分到/不在线）；
  - 某号槽 CRC 错 → 重复（两台同号）或异常；
  - 1 号槽异常 → 可能存在未分到号的从机（保持地址 1）→ 主机可再发“搜集信息”（增量模式：仅无 ID 从机参加）让其重试。

### 5.4 容错与边界

- 协商碰撞：随机退避 + 重试，轮数不限（分配耗时无要求）。
- 中途断电/上电：新加入设备没听到历史喊话，可能误占已占编号 → 对策：“搜集信息”可带**强制模式**（所有从机清零重协商），主机发现异常时用强制模式重来。
- 分配失败：从机保持地址 1，不告警；由主机“查看”发现并决定重跑。

## 六、必须确认的前提

1. **RS485 回环（自己发自己收）**：从机靠回环判断“本次喊话成功”。多数 RS485 收发器发送时接收端仍使能（RE 保持有效），MCU RX 能收到自己发的数据——**需在硬件上确认**；若无回环，退化为“主机查看+发现重复再重跑”兜底版。
2. **协商期间不中途断电/上电**；否则需强制模式重协商。

## 七、待确认事项

1. 硬件回环是否可用（决定“干净版”还是“查看+重跑兜底版”）；
2. “搜集信息”是否增加 1 字节“强制重协商”标志；
3. “查看”回报帧格式（建议极短帧，如 2 字节“我在此”）；
4. 确认后输出：帧字节定义、主/从机状态机、TRNG 初始化改动点（`hc32f4xx_conf.h` 打开 `LL_TRNG_ENABLE` + FCG0 时钟门控 + `TRNG_Init`）。
