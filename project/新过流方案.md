# 新过流方案（1ms 硬件中断驱动 ADC 均值 + 过流检测）

> 基于 `third` 分支（commit 23b6633）实现。
> 核心：把 ADC 均值滤波、电流换算、过流检测从主循环 1ms 轮询改为 **1ms 硬件中断**（TMR0_Unit2 CH A 心跳）执行；过流**事件发布仍走主循环**，保证下游 Flash/打印/电机仲裁链安全。

---

## 一、背景与目标

原方案：ADC 每 200µs 采样写入环形缓冲；主循环（≥1ms 轮询）取缓冲做均值滤波；dev_sensor 在主循环 1ms 读均值、算电流、做过流判定。

问题：主循环被其他任务（485、打印、电机仲裁等）拖慢时，均值计算和过流判定的执行时刻随之漂移，过流窗口的实际触发时间不稳定（实测 30ms~100ms 波动）。

目标：

1. dev_adc 均值、dev_sensor 电流换算、过流判定 → **硬件 1ms 精确节拍**，完全不受主循环耗时影响。
2. 事件发布 / 电机停转链路保持主循环执行（行为不变，避免 ISR 内做重活）。

---

## 二、总体架构

```
Timer0(200us) ──硬触发──> ADC SEQ_A 转换（电流CH5 + 电压CH4/CH6）
    │
    └─ EOCA ISR(优先级6)：读各通道值 → 写入各自环形缓冲(dev_adc)

TMR0_Unit2 CH A（1ms 心跳，优先级3）
    ├─ tickTimer_Update()                    // 系统心跳
    └─ TMR0_Unit2_1msTask()                  // App 层实现
        ├─ ADC_Device_Update(电流)           // 取空环形缓冲 + 全部样本均值
        ├─ ADC_Device_Update(电压)
        └─ Sensor_Device_UpdateIsr(电流传感器)
            ├─ 直接读 ADC 缓存均值（绕过 Device_Read 互斥锁）
            ├─ 电流换算（零点偏移 / 灵敏度）
            └─ 过流状态机（点数模式 / 时间窗口模式）
                ├─ 触发：置 u8OcTriggerPending + 记录电流/阈值 + LED
                └─ 恢复：置 u8OcReleasePending（仅 AUTO 清除模式）

ESystem_MainLoop 最顶部
    └─ ProcessSensorPendingEvents()
        ├─ u8OcTriggerPending → EventBus_Publish(TOPIC_CURRENT_ALARM, active=1)
        └─ u8OcReleasePending → EventBus_Publish(TOPIC_CURRENT_ALARM, active=0)
            └─ RTurn_OnCurrentAlarm / FaultHandler_OnCurrentAlarm（打印/Flash/仲裁都在主循环）
```

---

## 三、关键设计决策

### 1. 检测放 ISR，发布放主循环

`EventBus_Publish` 是**同步执行订阅回调**。`TOPIC_CURRENT_ALARM` 的订阅链实际会执行：

```
RTurn_OnCurrentAlarm → RTurn_HandleOvercurrent
    ├─ RTURN_OUT / MAIN_D 打印
    ├─ RealTime_SetFault
    ├─ RunAngle_TryCalibrate → RunAngle_OnCalibration → Param_Save（Flash 擦写）
    ├─ EventBus_Publish(TOPIC_RTURN_LIMIT)               // 嵌套发布
    └─ RTurn_PublishBidirectionalOvercurrent → TOPIC_OVERCURRENT_FWD/REV → 电机仲裁
```

这些（尤其 **Flash 擦写**、打印、电机仲裁）绝不能跑在中断里：

- Flash 擦写耗时毫秒级且内部会关中断，会压掉 200µs ADC 采样、破坏 RS485 时序（正是之前排查过的丢包问题）；
- 心跳 ISR 优先级 3 **高于** ADC ISR 优先级 6，ISR 里活太长会直接丢采样，反而毁掉时间精度；
- RTurn / RunAngle / 电机队列 / DeviceManager 锁都不是为 ISR 设计，存在重入与并发风险。

因此：**检测（时间关键）在 ISR 内完成，只置一个标志；发布/停转（效果）留在主循环**。

### 2. 校准保留在主循环

`Sensor_Device_Update`（主循环版）在未校准时执行 120ms 阻塞延时 + 50ms 稳定采样校准；**已校准后直接 return**，由 ISR 快速路径接管。校准时电机不转（被阻塞），主循环 1ms 轮询完全够用，且阻塞延时只出现在主循环，不影响中断。

### 3. ISR 路径三无：无打印、无发布、无阻塞

- 纯整数/64 位运算，几十 µs 内完成；
- `DEV_SENSOR_TIMER_DEBUG` 已注释，避免时间窗口模式的 `SENSOR_TIMER_DBG` 在 ISR 里输出；
- 调试数据用 JScope 变量（`g_dbg_sensor_final_ma` 等）观察。

### 4. 关闭主循环双跑

`DeviceManager_DisableUpdate(ID_ADC_CURRENT / ID_ADC_VOLTAGE)`：这两个设备只由 1ms ISR 驱动；
`ID_SENSOR_CURRENT` 保留主循环轮询（仅校准用，已校准后 no-op）。避免同一份环形缓冲/状态机被两处同时消费。

### 5. 直接读 ADC 缓存，绕开锁

`Sensor_Device_UpdateIsr` 通过 `DeviceManager_Get()`（纯数组访问，ISR 安全）拿到 ADC 设备指针后**直接读** `u16RawValue / u16VoltageMv`，绕开 `Device_Read` 的互斥锁（锁内含 `__disable_irq` / `while(1)`，非 ISR 安全）。

### 6. 过流状态机改为置标志

点数/时间窗口两种模式的 `EventBus_Publish` 全部改为置 pending 标志，并**记录触发时刻的电流与阈值**（`s32PendingCurrentMa / s32PendingThresholdMa`），保证主循环发布时事件载荷准确（而不是发布时读到的“最新值”）。手动/485 清除（`Sensor_Device_ClearAlarm`）会同步清 pending 标志。

## 五、时间精度与边界

- **均值、电流、过流判定**：1ms 硬件节拍，与主循环无关；过流窗口按 1ms 累计，精度由硬件保证。
- **发布 / 停转**：主循环最顶部处理，最坏延迟约一个主循环周期；此前实测 trigger→estop ≈ 0µs。
- **ISR 时长必须 < 200µs**：心跳优先级（3）高于 ADC（6），超时会把 200µs 采样压掉。当前 ISR 路径为整数/64 位运算，远小于该上限。
- **485 运行中改阈值/窗口**：32 位读写原子，ISR 下一拍生效；如需更强一致性可“改参时预计算原始阈值”。
- `Sensor_Device_Update` 旧“已校准”代码块当前不可达（被 early-return 挡住），代码保留，待编译验证后清理。

## 六、验证建议

1. Keil MDK 编译无错误。
2. JScope 观察 `g_dbg_sensor_final_ma` / `g_dbg_current_filtered_ma`，确认 1ms 更新节奏。
3. 堵转实测：示波器对比过流触发到停转时间，过流窗口应稳定（如 40ms 窗口 → 40ms ±1ms）。
4. RS485 通讯测试无丢包（ISR 已无打印，心跳 ISR 保持轻量）。
